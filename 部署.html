    11. 部署

    在开发阶段，有两个服务器协同工作：[Angular] 开发服务器（客户端）和 JSON 服务器（API）。在生产环境中，只有一个：

    1. 构建客户端。在 [rdvmedecins-angular] 文件夹中：

    npm run build

    [dist/rdvmedecins-angular/browser/] 文件夹包含整个应用程序：一个 [index.html] 页面、一个样式表，以及经过优化的 [JavaScript] 文件（[Angular] 的代码、路由器、[ngx-translate]……以及我们自己的代码）：

    • 初始文件在启动时下载：经服务器压缩后约 135 KB；
    • 每个按需加载的页面（[loadComponent]）都有自己的文件，在首次访问时下载；
    • 每个文件的名称都包含其内容的哈希值（[main-3NXKYGU5.js]）：新版本将具有不同的名称，因此浏览器永远不会缓存过时的版本；
    • 编译器已检查在 [angular.json] 中设置的预算：出现警告则表示应用程序已变得过大。

    2. 上传到服务器。将 [dist/rdvmedecins-angular/browser/] 文件夹的全部内容复制到 JSON 服务器根目录下的 [client/] 文件夹中（[rdvmedecins-nestjs-json/client/index.html]、[rdvmedecins-nestjs-json/client/main-3NXKYGU5.js]……），然后重启服务器。它显示：

2
    [Nest] LOG [RdvMedecins] Angular client served from .../rdvmedecins-nestjs-json/client
[Nest] LOG [RdvMedecins] JSON server started: http://localhost:8080/api

    完整的应用程序现在可以通过 http://localhost:8080 访问。服务器提供客户端的文件，并对 /api 之外的任何其他 URL 返回 [index.html] ：重新加载 /schedule 页面也能正常工作（该页面是由客户端的浏览器显示的）。对此好奇的读者可以看看，执行这项任务的是服务器上的 [src/web/client-spa.ts] 文件。

    3. 在真实的生产环境中，不要忘记服务器上的 [.env] 文件：

    • 一个长且随机的 [JWT_SECRET]；
    • 一个空的 [CAPTCHA_TEST]；
    • [COOKIE_SECURE=true] 如果站点通过 HTTPS 提供服务（必须如此：因为要传输密码）；
    • [TRUST_PROXY=true] 如果服务器位于代理（[nginx]……）之后，以便尝试次数限制能看到客户端的真实 IP 地址。

    然后启动已编译的服务器：[npm run build]，接着执行 [npm run start:prod]。
